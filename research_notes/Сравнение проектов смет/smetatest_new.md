# Аудит smetatest/new

## Что это за продукт и какой пользовательский сценарий реализован

### Takeaway
Репозиторий содержит аккуратно оформленный статический демонстрационный калькулятор стоимости строительства частного дома, а не готовую систему составления смет. Пользователь выбирает несколько параметров дома и видит приблизительный итог по восьми укрупнённым категориям; хранения проектов, редактирования позиций, базы цен и настоящего AI в коде нет.

### Cited Findings
- Автор прямо называет проект прототипом для customer development и предлагает открыть `index.html` без сборки; заявленный стек прототипа — Vanilla HTML/CSS/JavaScript. — [README, строки 1–23](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L1-L23)
- Форма позволяет выбрать один из 6 регионов, этажность, площадь, высоту, тип фундамента, материал и толщину стен, кровлю, а в «детальном» режиме — окна, двери, фасад, отопление и отделку. — [Форма, строки 483–611](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L483-L611)
- Результат выводится только по 8 укрупнённым статьям: земляные работы, фундамент, коробка, перекрытия, кровля, проёмы, отделка/инженерия и накладные/прибыль. — [Панель результата, строки 615–657](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L615-L657)
- Расчёт предполагает квадратное пятно застройки (`4 * sqrt(footprint)`), использует жёстко записанные расценки и коэффициенты, добавляет 15% накладных и 8% прибыли. — [Расчётный движок, строки 36–87](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js#L36-L87)
- В фактическом дереве коммита находятся только `README.md`, `app.js`, `generate_sample_pdf.py`, `index.html` и готовый PDF; нет сервера, базы данных, AI-клиента, конфигурации внешних API или каталога цен. — [Дерево репозитория на коммите](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4)
- Next.js, FastAPI, Supabase, Claude, OCR, ЮKassa, Vercel и Railway перечислены как будущий production-стек, а не как реализованные компоненты. — [README, строки 25–31](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L25-L31)

### Inferences
- Название «AI-сметчик» здесь является позиционированием будущего продукта: в текущем коде нет ни модели, ни API-вызова, ни эвристического парсинга ТЗ.
- Проект годится как кликабельный макет для обсуждения идеи с другом или сметчиком, но получившийся итог нельзя считать локальной/объектной сметой в профессиональном смысле: нет состава ресурсов, нормативного обоснования, версий цен, ручного редактирования и проверяемого источника расценки.
- Главная инженерная сложность будущего продукта — не интерфейс и не Excel, а согласованная с практикующим сметчиком модель данных и расчёта.

### Gaps
- В репозитории нет доказательств заявленной точности ±10–15%, применения ФЕР или калибровки по реальным сметам; это утверждения README без методики и тестовых наборов. — [Заявление о точности, строки 54–62](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L54-L62)
- Не указано, для какого именно вида расчёта нужен инструмент другу пользователя: укрупнённая оценка ИЖС, коммерческое предложение подрядчика, локальная смета по нормам или свободная калькуляция работ/материалов.

## Архитектура, зависимости и запуск

### Takeaway
Веб-демо запускается предельно просто и может быть размещено на любом статическом хостинге. Отдельный Python-скрипт для PDF уже требует `reportlab` и системных шрифтов, но зависимости и воспроизводимая инструкция для него отсутствуют.

### Cited Findings
- Статическая часть состоит из одного HTML-файла со встроенными стилями и одного ES6-скрипта; `app.js` подключён обычным `<script src="./app.js">`. — [index.html, строки 676–689](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L676-L689)
- Состояние расчёта хранится только в JavaScript-объекте в памяти страницы, а обновление DOM выполняется через `textContent`. — [app.js, строки 10–24 и 90–103](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js#L10-L24)
- README даёт только инструкцию открыть `index.html` и сообщает, что проект можно разместить на статическом хостинге. — [README, строки 7–23](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L7-L23)
- PDF-скрипт импортирует `reportlab` и регистрирует DejaVu по абсолютным Linux-путям `/usr/share/fonts/truetype/dejavu/...`. — [generate_sample_pdf.py, строки 8–24](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/generate_sample_pdf.py#L8-L24)
- В дереве нет `requirements.txt`, `pyproject.toml`, `package.json`, Dockerfile или workflow CI; также отсутствует упомянутая в README папка `docs/`. — [Дерево репозитория на коммите](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4); [README о docs, строки 13–18](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L13-L18)
- Ссылки на GitHub Pages, GitHub в верхнем меню и репозиторий в футере оставлены шаблонными (`your-username`, корень github.com, `your-repo/smeta-ai`). — [README, строка 11](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L11); [index.html, строки 458–468 и 670–673](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L458-L468)

### Inferences
- Для показа другу достаточно скачать 3 фронтенд-файла и PDF или включить GitHub Pages; сервер и Supabase для этого не нужны.
- Воспроизведение PDF-генератора на macOS/Windows без изменений не гарантировано: потребуются установка `reportlab` и переносимый поиск шрифтов.
- Если приложение должно сохранять несколько объектов одного пользователя, историю версий и собственные прайсы, текущая архитектура почти не сокращает работу над backend-частью; повторно использовать проще всего дизайн и некоторые формулы.

### Gaps
- Нет зафиксированных версий Python и ReportLab, поддерживаемых браузеров или инструкции по деплою конкретной рабочей демоверсии.
- Нет доказательства, что GitHub Pages для репозитория включён; README содержит лишь шаблонную ссылку.

## Реальность Excel и PDF-выгрузки

### Takeaway
Excel-выгрузки нет вообще. Кнопка PDF открывает один заранее сгенерированный трёхстраничный пример, данные которого жёстко записаны в Python и не связаны с параметрами текущего расчёта в браузере.

### Cited Findings
- В roadmap генерация PDF и Excel указана только для будущей версии v1 с оценкой автора 8–10 недель. — [README, строки 64–76](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L64-L76)
- Текущая кнопка «Скачать смету · PDF» показывает модальное окно, после чего открывает статический файл `sample-smeta.pdf`; расчётные данные в URL, параметрах функции или запросе не передаются. — [index.html, строки 659–683](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L659-L683); [обработчик, строки 160–169](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js#L160-L169)
- Python-генератор содержит фиксированные реквизиты подрядчика, клиента, объекта и 24 строки работ в 8 разделах; входных параметров, чтения JSON или связи с `app.js` нет. — [generate_sample_pdf.py, строки 310–399](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/generate_sample_pdf.py#L310-L399)
- В дереве нет кода или зависимости для XLS/XLSX/CSV; присутствуют только HTML, JavaScript, Python и готовый PDF. — [Дерево репозитория на коммите](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4)

### Inferences
- Расчёт по исходным значениям UI даёт примерно 3,81 млн ₽, а сумма жёстко записанных строк PDF с 15% накладных и 8% прибыли — примерно 4,14 млн ₽. Это два независимых набора данных, поэтому статический PDF нельзя считать экспортом показанного расчёта.
- Добавить простой `.xlsx` из восьми итоговых категорий технически несложно, но это будет экспорт укрупнённой оценки, а не полноценной сметы. Правильный порядок — сначала создать единый структурированный расчёт (раздел → позиция → единица → количество → цена → сумма → источник/дата), а уже из него формировать HTML, XLSX и PDF.
- Если другу нужен привычный редактируемый Excel, разумнее сделать Excel главным выходным форматом первой версии и отложить PDF, оплату и AI до проверки расчётной модели.

### Gaps
- Не задан желаемый шаблон Excel: листы, колонки, формулы, группировка, НДС, материалы/работы, реквизиты, печатная форма и совместимость с существующим файлом друга.
- Нет эталонной сметы, по которой можно проверить соответствие выгрузки рабочему процессу.

## Качество, безопасность и целостность расчётов

### Takeaway
Для локального демо риск утечки данных низкий, потому что данные никуда не отправляются и не сохраняются. Для реального использования ключевой риск — не классическая веб-безопасность, а недостоверность и непрослеживаемость результата: клиентские коэффициенты, слабая валидация, отсутствие тестов и независимый PDF.

### Cited Findings
- В коде нет `fetch`, XHR, WebSocket, localStorage/sessionStorage или backend-вызовов; состояние живёт только в объекте `state`. — [app.js целиком](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js)
- Все коэффициенты и расценки находятся в открытом HTML/JavaScript и могут быть изменены пользователем в браузере. — [Начальное состояние](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js#L10-L24); [коэффициенты и ставки в форме](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L494-L608)
- HTML задаёт, например, площадь 40–500 м² и высоту 2,4–4 м, но обработчик JavaScript принимает любое неотрицательное число и не проверяет эти предметные границы. — [HTML-поля, строки 516–524](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/index.html#L516-L524); [обработчик чисел, строки 134–149](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/app.js#L134-L149)
- Репозиторий не содержит тестов, тестовых фикстур, CI или проверки результатов на эталонных сметах. — [Дерево репозитория на коммите](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4)
- README заявляет MIT, но отдельного файла `LICENSE`/`COPYING` со стандартным текстом и copyright notice в дереве нет. — [README, строки 98–100](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L98-L100); [Дерево репозитория](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4)

### Inferences
- Пока это локальный инструмент одного знакомого, отсутствие авторизации не проблема; при размещении с клиентскими данными потребуются модель доступа, резервное копирование, журналирование версий и правила обработки персональных данных.
- Нельзя доверять клиентскому итогу для счетов/договоров или оплаты: расчёт должен повторно выполняться или проверяться на доверенной стороне, а версия прайса и входные параметры — сохраняться вместе с результатом.
- До коммерческого повторного использования стоит уточнить лицензию у автора или получить полноценный MIT `LICENSE`: строка в README выражает намерение, но не содержит стандартных условий и notice.

### Gaps
- Неизвестно, проходили ли формулы профессиональную проверку вне репозитория.
- Не проводился юридический анализ достаточности декларации MIT в README; замечание выше — техническая осторожность, не юридическое заключение.

## Реалистичная сложность использования и доработки

### Takeaway
Показать текущий прототип можно за часы. Превратить его в полезный личный калькулятор с редактируемыми позициями и Excel — задача порядка нескольких дней или недель после согласования модели; коммерческий продукт из README требует отдельной разработки и предметной верификации, а не «внедрения» готового решения.

### Cited Findings
- Авторская оценка будущего MVP с аккаунтами, оплатой, PDF/Excel, 100+ позициями и AI-парсингом — 8–10 недель; зрелой версии — 4–6 месяцев. — [Roadmap, строки 64–82](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L64-L82)
- Текущий код уже даёт UI и простую модель расчёта без сборки, но не содержит ни одной из серверных функций будущего MVP. — [README о текущем v0 и v1](https://github.com/smetatest/new/blob/42e66e29ca112de502ae867ab39a0332c686a1a4/README.md#L64-L76); [Дерево репозитория](https://github.com/smetatest/new/tree/42e66e29ca112de502ae867ab39a0332c686a1a4)

### Inferences
- **Просто показать другу:** 1–4 часа на скачивание, замену заглушек/бренда и публикацию статических файлов; результат останется демонстрацией.
- **Экспорт текущих 8 агрегатов в XLSX:** ориентир 0,5–2 рабочих дня, включая форматирование и ручную проверку нескольких сценариев. Ценность будет ограниченной из-за слишком грубой структуры.
- **Личный инструмент для одного специалиста:** ориентир 1–3 недели для таблицы позиций, справочника собственных цен, разделения работ/материалов, редактирования, сохранения проектов и качественного XLSX-шаблона — при наличии готового эталона от друга.
- **Небольшой многопользовательский сервис:** ориентир 2–4 месяца для команды/сильного full-stack разработчика плюс постоянное участие сметчика; сюда входят auth, БД, версии цен, права доступа, экспорт, тесты, резервирование и эксплуатация. AI/OCR и автоматические прайсы лучше оценивать отдельными этапами.
- Самый практичный вариант переиспользования: взять визуальную идею и, возможно, базовый HTML, но проектировать расчётные сущности и Excel-выгрузку заново под реальную смету друга.

### Gaps
- Оценка может измениться в разы после получения образца Excel и ответа, нужны ли нормативные ФЕР/ТЕР, Гранд-Смета/АРПС-совместимость, совместная работа и облачное хранение.
- Неизвестны требования к размещению, количеству пользователей, конфиденциальности и импорту существующих прайсов.
